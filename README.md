# Fuel Tracker

PWA для обліку пального, опублікована через GitHub Pages.

## Де редагувати код

Редагуй лише вихідні файли в `src/`:

- `src/index.template.html` — каркас сторінки;
- `src/styles.css` — оформлення;
- `src/js/state.js` — стан, IndexedDB і розрахунки;
- `src/js/views.js` — формування екранів;
- `src/js/actions.js` — натискання, форми, імпорт та експорт;
- `src/js/app.js` — запуск і фінальне малювання інтерфейсу.

Не редагуй кореневі `index.html` і `sw.js` вручну: це результати збірки.

## Як зібрати і опублікувати зміну

Після зміни файлів у `src/` виконай:

```sh
node scripts/build.mjs
```

Якщо встановлений npm, також працює `npm run build`.

Скрипт генерує один `index.html` для GitHub Pages та новий `sw.js`. Коміть і пуш у `main` мають містити разом:

```text
src/
scripts/build.mjs
index.html
sw.js
```

`index.html` — готова автономна версія програми, яку завантажує телефон. Зміна вихідників без нового `index.html` не потрапить у PWA.

## Офлайн-робота PWA

`sw.js` кешує `/Fuel-track/` та `/Fuel-track/index.html`. Версія кешу автоматично містить хеш збірки, тому після кожного нового build Chrome бачить оновлення й видаляє попередній кеш `palne-*`.

Після публікації на GitHub Pages:

1. Відкрий програму на телефоні один раз з інтернетом.
2. Повністю закрий PWA.
3. Відкрий її знову та, за потреби, перевір без інтернету.

Не змінюй адресу сайту `/Fuel-track/`, ключі даних або формат записів без окремої міграції: дані користувача зберігаються у браузерній IndexedDB, а старі копії можуть бути в `localStorage`.

## Перевірка перед пушем

Запусти build двічі: виведений хеш має бути однаковим. Також перевір, що в `sw.js` є поточний `palne-<hash>` і шляхи `/Fuel-track/`, `/Fuel-track/index.html`.

Після пушу відкрий [опубліковану програму](https://lemon-fresh-air.github.io/Fuel-track/) у браузері. Для повної перевірки встановленої PWA виконай три кроки з розділу «Офлайн-робота PWA».
